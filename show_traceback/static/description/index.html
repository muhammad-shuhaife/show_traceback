Set it up in four steps

  1. Install the matching addon.
    Deploy the show_traceback folder, reload all workers and install or upgrade it in Apps. Remove the Apps filter when searching for this technical addon.
  2. Choose the URL in debug Settings.
    As a Settings administrator, enable developer mode and open Settings → Error Traceback. Enter a name such as my_error.
  3. Save and authorize your browser.
    Click Save, then Open traceback while Odoo is working. Repeat this after upgrading from an older package.
  4. Reproduce the failure and refresh.
    Use the same browser and hostname to open http://localhost:8069/my_error. The page shows the latest captured exception.

Access & operating limits

Browser authorization lasts up to eight hours. It uses a separate HttpOnly cookie issued after administrator authentication. It survives Odoo session rotation and logout. Delete the odoo_traceback_* browser cookie to end access early.

  • The addon must load successfully in each serving worker before a failure. It cannot serve a page when the Odoo process is stopped.
  • Authorize the browser in advance. A different browser or expired grant needs normal administrator authentication while Odoo is healthy.
  • Only newly captured unexpected request exceptions appear. Expected user/access errors and HTTP 4xx responses are excluded.
  • Workers must share Odoo's writable data directory. Startup failures before addon loading and background-job errors may still need server logs.
  • Installing Python addons requires deployment and a worker reload. Changing the configured URL afterward needs only Save.
